**Status:** scoping, approved by the owner 2026-09-24 as the program's scope.

lands, its substance moves into `docs/magic/{MODEL,DECISIONS,ROADMAP,TESTING}.md`

## Context

`docs/ROADMAP.md` names magic "the largest unbuilt area" and already holds two
primitives waiting for it: `lib/fields.mjs` `spellRefField()` (a uuid pointer at
the core spell item, placeholder for a real spell primitive) and `lib/vocab.mjs`
`VALUE_SCALES` (`arcaneValue` / `divineValue`, unconsumed). The owner wants the
whole system scoped: casting and tracking, the alternate magic types (JJ ch. 15
plus the Annals of the North eldritch supplements), magic items (JJ ch. 4,
extended by the Treasure Tome where forward-compatible), magical research (RR
ch. 8 / JJ), UI, multi-target and summon tracking, importing the full spell list
(RR ch. 5), and the JJ ch. 14 custom-spell math — the shared infrastructure the
printed spells were built on, extended by AXIOMS — so that custom spells are
easy to set up and every repeated effect kind is a dedicated enum, the way
weapon types already are.

The deliverable of the scoping session was the scope: feature decomposition,
data model, what is reused from core, what the importer must extract, the UI
surfaces, release phasing, live-test recipes, and the open questions. No code.

## Constraints that shape every choice (from doctrine, not restated elsewhere)

- **Structure ships, content is imported** (`.claude/rules/ip-doctrine.md`;
  template DECISIONS 2026-07-19, 2026-08-15, 2026-09-03). Spell text, spell
  values (range, duration, damage dice), item tables, research costs, magic-type
  parameter values, and the custom-spell cost tables are all CONTENT. They reach
  a world through `scripts/importer/` from the GM's own PDF. What ships is the
  procedure (how a spell resolves, which knobs a magic type has, how a design
  cost becomes a level) and the ENUMS (effect kinds, save categories, magic-type
  ids) — "automation vocabulary stays code" (2026-07-19 corollary).
- **Reuse → extend → enhance → invent** (TOOLCHAIN §6). Core's `spell` item and
  actor casting fields are reused; extras data goes in `flags["acks-extras"]`
  or in an extras sub-type only where core has no document for it; core is
  never edited; a wrapped core method has ONE owner and defaults to `scripts/lib/`,
  living in a feature only where the behaviour is unique to that feature's domain
  and `docs/<feature>/MODEL.md` records why (CLAUDE.md "Conventions").
- **Every release ships the Judge tools for what it adds** (CLAUDE.md
  "Release"): a schema without an importer recipe and a sheet that can populate
  it is half a feature. The importer recipe lands in the same motion ("a
  replacement that does not exist yet is not a replacement", template DECISIONS
  2026-08-15; TOOLCHAIN §10e itself no longer applies inside extras — both halves
  are one commit).
- **§10d/§10f apply to every new persisted flag**: `scripts/magic/uninstall.mjs`
  on the `equipment/uninstall.mjs` precedent (strips the spell, magic, spellEffect,
  magicItem and research data; macro + API), plus README "Disabling &
  uninstalling" and "Getting started" sections per feature.
- **Live testing is the gate** (`.claude/rules/live-testing.md`); every new
  surface needs `docs/magic/TESTING.md` before its first tag.
- **UI layout contract** (`.claude/rules/ui-layout.md`): every window in the
  scroll contract, type off the `--acks-fs-base` knob, no literal ids in
  templates.
- **Enum pattern**: a new CODE enum is declared in `lib/vocab.mjs` as a descriptor
  map (weapon categories are the frozen-map + membership-set variant in
  `equipment/config.mjs`), reaches fields via `choice()`/`choiceSet()` in
  `lib/fields.mjs`, and takes labels from `ACKS-LIB.<enum>Label.<key>` in
  `lang/en.json` (a new convention — today's vocab maps carry inline labels);
  validate cannot prove member-label completeness, so each enum ships a suite
  test. A code enum exists only where the engine branches on its members; a list
  a reader picks from ships EMPTY as an open vocabulary family and is filled by
  the importer (IP doctrine's option-list clause) — see "Effect enums".

## What Foundry v14 itself provides — REUSE (verified in the local client source)

- **Effect expiry is core now.** `ActiveEffect` carries `start {combat, combatant,
  initiative, round, turn, time}` and `duration {value, units, expiry, expired}`;
  units are years…seconds plus `rounds`/`turns`; `expiry` names an event
  (`combatStart|roundStart|turnStart|combatEnd|roundEnd|turnEnd`, or any
  module-defined string). `ActiveEffect.registry` (an `ActiveEffectRegistry`)
  refreshes on every combat event and on `updateWorldTime`, and the active GM
  performs `CONFIG.ActiveEffect.expiryAction` (`"update"` = sets
  `duration.expired`, default; `"delete"`). `Actor#onUpdateEffectDurations` is a
  hook point. So the module never ages effects itself: it writes a correct
  `duration` + `expiry` at cast time and reacts to `duration.expired` — with one
  seam it must close itself, rounds that outlive their combat (see Tracking).
- **ActiveEffect sub-types exist** — `ActiveEffect` has `type` + `system`
  (TypeDataField), `module.json` `documentTypes` accepts any document with
  `hasTypeData` (`common/packages/sub-types.mjs`), and a model must extend
  `foundry.data.ActiveEffectTypeDataModel`. The tracking design does NOT use one:
  a flag-marked base effect read through a DataModel carries "which spell, cast by
  whom, save result, what it does" with no relaunch and no residue when the module
  is off (see Tracking for the ruling and its counter-argument).
- Combat lifecycle hooks: `combatStart`, `combatRound`, `combatTurn`,
  `combatTurnChange`; `Combat#_onStartTurn/_onEndTurn/_onStartRound/_onEndRound`
  are protected (core `acks` overrides `nextTurn`/`nextRound`; extras already
  wraps `nextRound` in `lib/patches/combat-round.mjs`).
- `game.user.targets`, `MeasuredTemplate` and `canvas.templates` exist and are
  unused by core `acks`.

## What core (`acks` system, 14.0.1, `master`@9868568) already provides — REUSE

Core's magic is thin; the extras layer is nearly the whole system.

- **`spell` Item** (`src/module/data/item/spell-data.mjs`): `lvl`, `class` (free
  text; packs use "Arcane"/"Divine"), `duration`, `range` (display strings),
  `roll` (raw formula string; 12 of 19 shipped ones are not parseable), `save`
  (`death|implements|paralysis|blast|spell`), `memorized` (dead), `cast`
  (counter), `favorite`, `description`. Spells get an Effects tab; effects on a
  spell transfer to its OWNER (not cast-time).
- **Actor**: `system.spells.enabled` (the "Spellcaster" tweak; shows the tab),
  `system.spells.{1..6}.max` (hand-entered; no L0 or L7+), `details.casterlevel`
  (declared, never read). No caster type, no repertoire, no memorization.
- **Casting**: every route ends in `AcksItem#spendSpell` → `update({cast+1})` +
  `show()`. No max check, no targets, no roll, no effect, no hook, no return.
  Chat card (`templates/chat/item-card.hbs`) carries actor/item/token ids, a
  Save button (rolls `rollSave` for CONTROLLED tokens, not targets) and a Roll
  button. Core's `chatListeners` intercepts every `.card-buttons button` in any
  message — a module card must not use that class, or must route through it.
- **Saves**: `AcksActor#rollSave(save, options)` — `1d20 + save.mod + wis.mod`
  vs `system.saves[save].value`; no bonus parameter; it opens its own dialog
  (skipped by the world's configurable `skip-dialog-key`, read through extras'
  `lib/roll-dialog.mjs` `skipDialogFor`), posts its own chat card, and returns
  `undefined` on cancel — usable for a single save, wrong for N per-target saves.
- **Damage**: `AcksActor#applyDamage(amount, multiplier)`; `chat.mjs` adds an
  apply button to any `.damage-roll` element in any message — a module card
  gets it free.
- **Multi-target**: only `targetAttack` iterates `game.user.targets`.
- **Magic items**: nothing. Reusable seams: `item.quantity`, `weapon.counter`
  (charges-shaped, monster sheet decrements it), `weapon.bonus`, `armor.aac`.
  Effect targets that SURVIVE derived-data recompute: `system.aac.mod`,
  `thac0.mod.{melee,missile}`, `damage.mod.{melee,missile}`, `save.mod`,
  `initiative.mod`, `movement.mod`, `scores.<x>.value`, `saves.<x>.value`.
  Overwritten (useless as AE targets): `aac.value`, `initiative.value`,
  `thac0.bba`, `scores.<x>.mod`, encumbrance, `hp.bhr`.
- **Statuses**: `CONFIG.ACKS.statusEffects` — surprised, overnumbering, done,
  readied, delayed, slumbering; combat cleanup clears them; no expiry logic.
  Combat tracker has a "Casting" toggle — a COMBATANT flag `flags.acks.prepareSpell`
  (`combat-helper.mjs`), marker only.
- **Packs**: `acks.acks-arcane-spells` (56, L1–4) and `acks.acks-divine-spells`
  (19, L1–2) with full book description text; `acks-treasure` roll tables
  (magic item NAMES only, 6 tables); proficiencies incl. the magic ones as
  plain abilities. Two empty pack-folders "Classes" and "Spells" under the RR
  folder. Link to core spells by UUID; never copy their text.
- **Class/spell progression, research, effect kinds, magic settings, custom
  hooks, spell API**: none. `game.acks` = `macro.rollItem`, `commands`,
  `debug`.
- **Wrap targets** (bundle is minified: reach classes only via `CONFIG.*`):
  `CONFIG.Item.documentClass.prototype.spendSpell` (the one cast choke point),
  `.show`, `.getChatData`, `.use`; static `_getChatCardTargets`,
  `chatListeners`; `CONFIG.Actor.documentClass.prototype.rollSave`,
  `applyDamage`, `targetAttack`, `computeAdditionnalData`. **Already owned in
  extras**: `rollFormula`/`getTags` (`scripts/abilities/roll-wrap.mjs`),
  `rollAttack` (`lib/patches/attack-roll.mjs`), `rollInitiative`/`nextRound`
  (`lib/patches/`), `computeEncumbrance` (equipment), `getTotalWages`
  (henchmen). One owner per method: spell work on `rollFormula` goes through
  the abilities owner.
- **Unmerged core branches** to design around: `feat/unified-ability-rolls`
  (`system.rolls[]`, `game.acks.lib.VALUE_SCALES`; spells NOT migrated — cards
  lose their Roll button) and `190-weapon-rework` (save migration moves).
- **`acksii-compendia`** (a community module by Citard, installed beside the
  family repos; compiled packs only, no source): arcane/divine spells II,
  rituals, potions, rings, scrolls, misc magic, swords, magic weapons,
  implements. Not canon, not a dependency, never a source; but any `spell` Item
  from it works with an extras layer that keys on the Item, so a GM who has it
  loses nothing.

## The rules surface, as structure (headings and shapes only; no values)

**Spells (RR ch. 5).** §V.1 casters and castings per day; §V.2 lists by magic
type; §V.3 repertoires — a 2×2 matrix (arcane/divine × prayerful/studious):
prayerful = order repertoire + prayer requirement; studious = spell book, study
requirement, starting repertoire, acquiring formulas, adding/replacing, recovering a
lost book; §V.4 reversal; §V.5 signatures; §V.6 **13 spell types** (blast, death,
detection, elemental, enchantment, esoteric, healing, illusory, movement, protection,
summoning, transmogrification, wall; necromancy exists only as a code/tag); §V.7 six
lists (arcane 216, divine 180, bladedancer 60, crusader 60, priestess 90, shaman 60
entries); §V.8 **317 spell entries** — format = name, magic type+level, spell type,
range, duration, prose; 25 defined terms (affected creature, recipient, target,
beholding, touch, caster level, concentration, stationary concentration, dispelled,
enchanted creature, perpetual, indefinite, special…). **No area/target/save/
casting-time/component field exists — all of it is prose.** Stat-line value SHAPES:
range takes 11 shapes (a distance, miles, touch, self, special, per-level,
touch-or-distance…), duration 41 (instantaneous, concentration, stationary
concentration, perpetual, indefinite, permanent, special, a count of rounds/turns/
hours/days/weeks, per caster level, concentration plus a count, dice-rolled). Class
tags per spell (12 classes) and school tags (14, multi-valued) exist only in the wiki
oracle's HTML as per-spell embedded data (slug, level, magic type, classes, schools,
reverse-of) — **its markdown lost every stat line**, so the HTML is the register's
oracle and the printed page is what wins.

**Classes (RR ch. 2).** 12 casting classes; each has a progression table with
spell-level columns 1–6 (or 1–5), two with a Caster Level column (nightblade,
ruinguard), one dual (wonderworker: arcane and divine columns side by side); magic
powers as labelled paragraphs (arcane/divine magic, research tiers, sanctum/temple,
rebuke undead + its table, dark paths, traditions, totem, spell storing…); templates
print starting spellbooks under equipment. Non-casters with magic hooks: thief
(deciphering, scrollreading), bard (arcane dabbling), paladin. RR ch. 3: ~24 magic
proficiencies.

**Casting in combat (RR ch. 6).** Declaration relative to initiative; the
disruption rule; line of sight and beholding; area effects; casting time by source
(repertoire, scroll, implement, spell-like ability); saves by category with cover
and size adjustments; conditions and the concentration rules in Appendix B
(bewitched, dominated, enslaved, enthralled, mesmerized, petrified, slumbering,
webbed…; concentrating, stationary concentrating); mortal-wounds modifiers from
healing and necromantic magic (Appendix C).

**Magic research (RR ch. 8 §VIII.8).** Every project has one template:
eligibility gate (class level, magic type, alignment) → component/material/research
costs → research throw with modifiers → facility (library, sample, formula, workshop,
mortuary, crossbreeding lab) → time from research rate; creature projects add a
control rule. Projects: spells, magic items (one-use, charged, activated by
frequency, at-will, permanent by duration tier, permanent bonus — an 18-row cost
table), identifying, constructs (design record + manufacture), crossbreeds,
necromancy, learning/casting rituals (20 sample rituals WITH stat lines), magic
experimentation (advantage, method, breakthrough, mishap, mutation tables).
§VIII.7 arcane power from dungeons; §VIII.9 congregants and divine power (domain
scale); §VIII.10 XP from research. Ch. 4: spellcasting services and availability by
market class, perpetual casting fees, magic in construction; ch. 12: spell damage
vs structures (20 rows).

**Magic items (JJ ch. 4).** Identifying, using (activation, charges — no recharge
rule), buying/selling/commissioning, availability by market class; Classic tables
(type d100 + potions ~85, rings ~21, scrolls ~27, implements ~24, misc ~68, swords
~18, armors ~10, misc weapons ~38) and Heroic rarity tables (common 31 … legendary
52); ~155 described entries (name → prose → Base Cost by effect → Apparent Value;
the Base Cost vocabulary = RR ch. 8 effect types); arms & armor by genre; 9 trait
tables; minor effects in crafting. No sentient items, no artifacts chapter.
**Treasure Tome** (346 pp, ~1,220 entries, 107 tables): new entry format
Description / Mechanics (Activation Time, Activation Frequency, Cancellation) /
Lore; a Gritty placement mode; ch. 3 item creation with advanced rules (cursed,
formula length, drawbacks, proficiency/power-granting, perpetual, periodic, random
lifespan, **rechargeable**, set powers, triggered, user restrictions); appendices:
item generation (powers, themes, command words), traits, corruption, weapon
development (bonded, empathic), potion miscibility, monsters. ACKS II supersedes on
conflict; the format is forward-compatible.

**Custom spells — the math (JJ ch. 14).** Inputs: spell type (11 buildable;
elemental = another type + modifier; esoteric unbuildable), one or more effects with
base costs and modifiers, and factors for target, range, duration, saving throw,
source. Build points = effect cost × factors, rounded; **level read off fixed bands
of build points**; breakthroughs raise the allowance. 67 tables: per type, Effects /
Range / Duration / Targeting / Saving Throw / Source (6 × 11) + the breakthrough
table. 85 printed worked builds (blast 8, death 10, detection 4, enchantment 12,
healing 6, illusion 13, movement 10, protection 5, summoning 3, transmogrification
6, wall 8). Sources: arcane, divine, eldritch. Effect-category labels per type are
the raw material for the effect enums (blast: damaging effects, max-damage
modifiers, additional effects, duration modifiers, target by number/area;
enchantment: target by HD/area, save modifiers; healing: cure/cause damage,
cure/inflict trauma; protection: armor, enhancements, invulnerabilities,
deflections/resistances, dispels/negations/wards; summoning: max HD, max special

discern vs locate). Lineage: PC (ACKS I) → HFH ch. 8 "The Math Behind the Math" →
**AXIOMS 18 "The Art and Science of Building Spells"** (merges PC + HFH; direct
ancestor) → JJ ch. 14. The chapter says most printed spells CAN be rebuilt, not that
they WERE.

**Custom magic types — the alternate systems (JJ ch. 15).** A magic type is a
bundle of ten settings over ONE casting model (castings per day from a progression
table): name; source factor per spell type (a worksheet: base modifier − type
modifier = variance × cost of variance = type cost; total = base XP cost); base XP;

### Data model — the spell primitive

**Reuse core's `spell` Item; extend under one flag.** `flags["acks-extras"].spell` is
a DataModel (`magic/spell-extras.mjs`, `SpellExtras`, on the `AbilityExtras`
pattern) because every consumer already keys on `type === "spell"` (character sheet,
follower card, `classes/grants.mjs`, formation, monsters, markets) and because core's
packs, the community `acksii-compendia` packs and hand-made spells are all spell
Items. Core's `lvl`, `class`, `range`, `duration`, `save` stay as the compat/display
surface and are WRITTEN from the structured flag (the importer and the sheet keep
them in step; `class` holds the primary magic type's label as core's packs do). A
sub-type was rejected: it would orphan every existing spell document and every
consumer.

`SpellExtras` fields (all enums below are defined under "Effect enums"):

- `lists: [{source, level, classes: []}]` — a spell prints on several lists at
  possibly different levels; `source` is an OPEN magic-type key (arcane, divine,
  eldritch, faery, gnostic, …, validated at runtime against the magic-type
  registry, never a code enum — ruling 2026-08-11), `classes` are class keys.
  `classes/grants.mjs` `choosableSpells` reads `lists[].source` FIRST and falls back
  to folded `system.class` — today it matches the folded class string only, so a
  spell on two lists is invisible to its second tradition; the same change dedupes
  the picker, preferring the imported copy of a spell over a core-pack copy of the
  same name (by cookbook id, else folded name). `hideSupersededPacks` was REMOVED by
  lib DECISIONS 2026-09-02 ("do not propose it again without new argument") and is
  not used here; the stale lines naming it in `docs/importer/ROADMAP.md` and
  `docs/classes/DECISIONS.md` are fixed in the same change.
- `type: choice(SPELL_TYPES)` (the table axis), `schools`, `elements`, `shade` —
  open-vocabulary keys validated against the world's vocabulary doc, not code enums.
- `range: {shape: choice(RANGE_SHAPES), value, unit: choice(DISTANCE_UNITS), perLevel,
  note}` and `duration: {shape: choice(DURATION_SHAPES), value, unit:
  choice(TIME_UNITS), perLevel, dice, plus: {value, unit}, concentration:
  choice(CONCENTRATION_KINDS), note}` — the shape is structure, the number is content
  (the importer parses the printed stat line into shape + value).
- `castingTime: {shape: choice(CASTING_TIME_SHAPES), value}`; `components: []` —
  open-vocabulary keys (HFH/BTA implements, trinkets, codices) validated against
  the world's vocabulary doc.
- `target: {model: choice(TARGET_MODELS), count: levelValueField(), hdPool:
  levelValueField(), area: {shape: choice(AREA_SHAPES), size: levelValueField(),
  height}, filters: choiceSet(TARGET_FILTERS), beholding: bool}`.
- `save: {category: choice(SAVE_CATEGORIES), effect: choice(SAVE_EFFECTS), perTarget:
  bool, modifier: levelValueField()}`.
- `reversible: bool`, `reverseOf: spellRefField()`, `reversedName` — one Item per
  printed entry heading (faithful to the page), pairs linked both ways; the cast
  dialog offers the pair. (`spellRefField()` becomes real here: `{uuid, name,
  cookbookId}` resolving through `lib/library.mjs`, and `effectField.spell` retires
  in favour of it — ROADMAP's promise.)
- `ritual: bool` (RR ch. 8 rituals, learned/cast through research), `invocation:
  {is, extemporaneous}` (BTA gnosis: castable at any available level, effects scale
  on invocation level), `ceremony: bool` (HFH/AotN).
- `effects: effectsField()` — the executable rows (REUSED `lib/fields.mjs` row shape,
  `type` widened to the magic kinds), each optionally carrying `build: {table, row}`
  — the locator of the imported JJ ch. 14 effect-table row it prices from.
- `build: {type, source, effects: [{row, count, picks}], target: row, range: row,
  duration: row, save: row, breakthrough, points, level}` — the builder's record;
  `points`/`level` are recomputed, never trusted.
- `notableUse`, `cite` (book/page — ships), provenance via the importer's
  `flags.acks-extras.cookbook` stamp as every imported document.

**Actor-side state** (`flags["acks-extras"].magic` on the caster, `magic/actor-magic.mjs`):
`repertoire: {[traditionKey]: [itemId…]}` (which owned spells are prepared/in the
repertoire; capacity comes from the class document via `classes/casting.mjs`),
`signature` (RR §V.5, per caster), `corruption: {points, weaknesses: []}` (eldritch),
`stigma: {[traditionKey]: n}` (gnosis/ceremonial — `RESOURCE_KINDS.stigma` exists),
`power: {arcane, divine}` (RR §VIII.7/9 ledgers), `concentration: {effectUuid}`,
`declared: {spellId, round}` (RR ch. 6 declaration; mirrors core's tracker marker
`flags.acks.prepareSpell`). Spent slots/points stay where they are
(`flags.acks-extras.classes.pools`, owned by classes). Owned spell items are the
caster's KNOWN spells (formulas/prayers); the spellbook item (`equipment/spellbook.mjs`)
grows from `{name, lvl}` to refs `{uuid, name, lvl}` (equipment ROADMAP "spell book
contents as documents"), so a lost book marks its formulas unavailable without
deleting anything.

### Effect enums — the "weapon types" of magic

Two tiers, and the line between them is the IP doctrine's own: **a code enum names a
mechanism the module implements** — a value the engine branches on, a table axis, a
stat-line shape — while **a list a reader picks from ships empty and is filled by
the importer** as an open vocabulary family (`lib/vocab.mjs` `SELECTION_VOCAB_DOC`
pattern: the family key is code, its members arrive from the page). A member is
promoted from the open family into the code enum only when the engine gains a
branch on it, and the DECISIONS entry names that branch. This satisfies the owner's
ask (dedicated enums, weapon-type style) without shipping a printed option list; the
strongest counter-argument — that these keys are common words and the family already
ships `DAMAGE_TYPES`, `CONDITION_KEYS`, `EFFECT_KEYS`, `NATURAL_WEAPONS` as code —
is rated MEDIUM: it covers the key names, not the membership, and membership is what
the page supplies (architect review, 2026-09-24). The owner may rule the other way;
it is listed under open questions.

Mechanics of the pattern, corrected against the source: vocab enums are descriptor
maps `{key: {label}}` with INLINE English labels read by `choicesOf()` — only
`ACKS-LIB.weaponCat.*` and `ACKS-EQUIPMENT.wear.*` use lang keys today, and
`optionsOf(ENUM, current, {blankLabel})` is a helper local to
`classes/class-sheet.mjs` (promote it to lib with the first magic sheet). New magic
enums use lang keys under `ACKS-LIB.<enum>Label.<key>` (a suffixed leaf so no key is
both a leaf and a prefix, §10m) and ship one suite test walking members against
`lang/en.json` — a NEW convention, recorded in lib's DECISIONS. Widening
`effectField` also needs the parameter fields the new kinds carry (heal kind,
summon creature/count/HD/control, transform aspect, wall properties, detect mode,
protection kind), a spell-side reading of `appliesTo` (today's `EFFECT_SUBJECTS`
self/opponent/ally is relative to an ability's owner; a spell needs caster / target /
recipient / area), and kind filtering by domain so the ability picker does not offer
spell-only kinds and `ability-sheet.mjs` `describeEffect` does not fall to its default
branch.

### The cost engine — one infrastructure for printed and custom spells

`magic/spell-cost.mjs` is pure (no Foundry), tested offline against invented tables,
and implements the PROCEDURE only: sum the chosen effect rows' costs (with count and
pick multipliers), multiply by the target, range, duration, save and source factors,
round by the printed rule, read the level off the band table, apply breakthrough
allowances. Every number comes from the world's imported `acks.spellBuilder` doc:
per type, six tables (effects / range / duration / targeting / save / source) whose
rows carry `{key, label, cost|factor}` from the page plus register-authored
structure `{kind: EFFECT_TYPES member, params}` so a row picked in the builder
expands into an executable effect row. The same doc is fed from JJ ch. 14 (primary),
AXIOMS 18 (the merged PC+HFH ancestor — registered as a second recipe for the same
doc id so a Judge holding only AXIOMS still gets the engine, and as a cross-check
during authoring) and HFH ch. 8 ("The Math Behind the Math", for the eldritch source
column). Magic-type source factors (JJ ch. 15) enter the same multiplication, which
is how a custom magic type prices its spells. Decomposition: the 85 printed worked
builds import as `build` records (JJ ch. 14 "Spell Builds" sections are content and
extractable); the remaining spells import with stat line + prose + register-authored
effect specs with locators, exactly as proficiencies do today (`DERIVE_PATTERNS`:
"the pattern ships; the number never does"). Extemporaneous spellsinging reuses the
engine at the table: build → transient spell → cast.

### Magic types — documents that publish rows

`acks-extras.magicType` Item sub-type (`magic/magic-type-data.mjs`), sheet mirrors
the class sheet (tabs: overview, builder, progression, repertoire & code, research,
saves, spell list). Fields follow JJ ch. 15's ten steps: `key`, `label`,
`sourceFactors: [{type, base, typeMod, variance, cost, typeCost}]`, `baseXp`,
`progression: {family, tier, delayed}` (42 imported grids in `acks.magicTypeBuilder`),
**`values: [{value, cost, fraction, slots, delayedSlots}]`** — the ladder
`classes/builder-logic.mjs` (`baseXpCost`, `deriveTradition`) actually prices from,
imported from the JJ ch. 12 grids or derived by the ch. 15 engine and stored —
`repertoire: choice(REPERTOIRE_KINDS)`, `casting: choice(CASTING_KINDS)`, `savesAs`,
`progenitor`, `code: {restriction, benefit}`, `categoryValue`, `research:
choiceSet(RESEARCH_KINDS)`, `saves: {rate, itemUsage, keyAttribute}`, `spellList:
{filter | refs}`, and the engine knobs the ACKS I systems need: `shade: {enabled,
corruptionThresholds, weaknessTable}`, `resources: {kind: slots|points|stigma,
costLadder, recovery, tapping}`, `ceremony: {performanceLadder, mishapTables,
implementsRequired, purification}`. **Publication goes to its OWN doc id,
`acks.magicTypes`, never into `acks.classBuilder`**: `lib/tables.mjs` holds one doc
per layer per id and merges per table, and `importer/builder-binding.mjs`
`applyBuilderImport` already writes `acks.classBuilder` at WORLD priority through
`ruledataImport.importDoc` — a second WORLD writer would race it and a WORLD
`magicTypes` table would replace the imported one whole, so "documents first, then
rows" cannot be expressed inside one doc. Instead `classes/builder.mjs`
`builderTables()` merges the two sources by `key` (a document wins over an imported
row of the same key; rows with no document remain). That merge is a classes change
and gets its own DECISIONS entry there; the 2026-08-11 ruling stands (no code enum
closes the set), and the race-as-document precedent supports documents. The
importer materializes the printed types as documents — arcane, divine, faery,
battlelore (JJ ch. 15 + the ch. 12 grids), eldritch (JJ shades + AotN ceremonies +
HFH list), gnostic (BTA), ceremonial and spellsinging (HFH). `VALUE_SCALES.arcaneValue
/ divineValue` get wired here (`powerValue` onto `levelValueField()`), or the entry
says why they stay inert (§10j).

### Casting engine and the resource engines

`magic/cast.mjs` owns core's `CONFIG.Item.documentClass.prototype.spendSpell` through
libWrapper — nothing wraps it today, so magic can be its one owner; the wrap is
feature-owned rather than in `scripts/lib/` on the abilities/equipment precedent, and
`docs/magic/MODEL.md` says why (the behaviour is unique to casting). The core
sheet's `#itemUse`, the hotbar `rollItem` macro and the extras sheet's `#onSpellCast`
all land here. **The wrap falls through to `wrapped()` for any item without
`flags.acks-extras.spell`, and skips capacity for an actor with no tradition**:
core's packs use spell items as MONSTER ATTACKS (Giant Centipede's bites, the Giant
Black Widow's web, the Dretch's stinking cloud), and those must keep core's card and
Save button untouched — a centipede bite is a release-2 regression check. Whether a
flagged cast still increments core's `system.cast` (which core's sheet displays) is
a DECISIONS call; proposed yes, so both sheets agree. Abilities' `roll-wrap.mjs`
already owns `rollFormula`/`getTags`; the cast card needs neither (damage rolls on
its own card, tags come from core's string fields), so neither is wrapped twice.
`castSpell(item, {actor, targets, tradition, reversed, casterLevel, source})`:
(1) resolve the tradition and its engine; (2) capacity and spend — slots and pools
through `classes/casting.mjs`, points cost by spell level from the type's ladder,
stigma/performance for gnosis and ceremonies, corruption bookkeeping for shaded
spells; (3) collect targets by `target.model` (`game.user.targets`, or tokens inside
a placed `MeasuredTemplate` for area spells, or self/touch); (4) saves per target
rolled INSIDE the cast card the way `formation/turn-engine.mjs` `rollPartySave` does
through `lib/roll-card.mjs` `renderRollCard` — core's `rollSave` opens a dialog and
posts a card per call and returns `undefined` on cancel, so it serves a single save
only; MODEL states which client rolls (the caster's seat rolls, the target's owner
may re-roll from the card); (5) execute
each effect row through `magic/execute.mjs` — a dispatcher keyed by `EFFECT_TYPES`:
modifier → AE change on the SAFE core targets only (`aac.mod`, `thac0.mod.*`,
`damage.mod.*`, `save.mod`, `initiative.mod`, `movement.mod`, `scores.*.value`,
`saves.*.value`); conditionGrant → status + AE; damage/heal → a roll card row with
`.damage-roll` so core's apply button works, halved/negated per `SAVE_EFFECTS`;
summon → tokens; resource → pools; immunity/resistance/movement/sense → AE;
everything else (illusion, wall, detect, transform, control, structural…) → a tracked
effect with duration and a card line, no arithmetic; (6) create the tracking effects;
(7) one chat card (extras template, NOT core's `.card-buttons` class, which core's
`chatListeners` intercepts) with per-target rows (`lib/roll-card.mjs`) and actions
(re-roll a save, apply, end effect, place/dismiss summon); (8) fire
`acksExtrasMagic.spellCast` (namespaced hook constant, literal `NAMESPACE`). Combat
declaration (RR ch. 6): when a combat runs, the cast dialog records the declaration
and sets core's tracker marker; damage to a declared or concentrating caster raises a
GM prompt, never an automatic cancel (TOOLCHAIN §10c). Scrolls, implements and
potions call `castSpell` with `{source: item, casterLevel: power's}` from
`magic-items`. Engines live in `magic/engines/{slots,points,stigma,corruption}.mjs`,
each pure with a thin document layer, and `magic/ceremony.mjs` holds the shared
ceremonial/gnostic procedure (performance throw vs the imported ladder → success
executes, failure adds stigma and rolls the tier's mishap table → GM applies;
lockout at the threshold; purification as a rest activity that clears stigma and
consumes trinkets). Rituals: `ritual: true` spells are learned and cast as research
projects (below) and executed by `castSpell` on completion.

### Tracking — durations, multi-target, summons, concentration

**A base ActiveEffect marked `flags["acks-extras"].spellEffect`, read through a
DataModel** (`magic/spell-effect-data.mjs`, the `SpellExtras` pattern, keyed the way
`lib/managed-effects.mjs` `registerManagedEffect(flagKey, labelKey)` keys an
effect by its flag) — not a sub-type. The flag route needs no world relaunch,
no `documentTypes.ActiveEffect`, no change to `sheet-claim.mjs` `DOCUMENT_NAMES`
(Actor and Item only), and with extras disabled a flagged effect still expires
natively, whereas a sub-typed one becomes an invalid embedded document on every
affected actor (the class of residue `tools/pack-data/cleanup.mjs` exists to reach
through `invalidDocumentIds`). A sub-type is chosen only with a DECISIONS entry
naming what the flag cannot do — the counter-argument (MEDIUM): a sub-type validates
on write and gets a per-type config sheet; the flag validates on read, and its
config section is injected into the base `ActiveEffectConfig` on the render hook
(`lib/managed-effects.mjs` has no sheet hook of its own — it offers
`lockManagedEffectRows` to sheets that list effects). If ever taken, the model MUST
extend `foundry.data.ActiveEffectTypeDataModel` and spread `super.defineSchema()`
(v14 keeps `changes` in `system.changes`; `_initialize` and `prepareBaseData` iterate
it), and `system.isSuppressed` must stay `undefined` when not deciding or it hides
`duration.expired`. Flag fields: `spellUuid`, `castId`, `casterUuid`, `casterLevel`,
`tradition`, `role: target|caster|summon|area`, `saveResult: {rolled, total, target,
success, category}`, `rows: effectsField()`, `summons: [uuid]`, `concentration`,
`dismissable`. Maps keyed by tradition and every optional key are retracted with
`-=` on write (§10h). One effect per affected target (multi-target = N effects
sharing a `castId`), one on the caster for caster-side clauses or concentration, one
on each summoned actor. Registered as managed effects, so "end effect" goes through
`managedDelete` and the `preDeleteActiveEffect` guard; a ruling in lib GROUPS says
whether spell effects survive a group recall (`group-logic.mjs` `isDerivedEffect`).

**Durations** map ACKS shapes onto Foundry v14 `duration` + `expiry`: rounds →
`rounds` with `start` from the running combat; turns / hours / days / months →
seconds-based units (ACKS weeks become days — Foundry has no weeks unit);
concentration → indefinite + the flag, released by the caster's next action or the
damage prompt; permanent / perpetual / indefinite → no duration. **Rounds cannot be
left as rounds past combat**: `_prepareCombatBasedDuration` converts through
`CONFIG.time.roundTime`, which core `acks` leaves at 0 and only reads, so a rounds
effect whose combat ends is reframed with `seconds: null` and never expires; setting
`roundTime` would change core's `nextRound` time advance and double-count with
`formation/combat-bridge.mjs`. So on `combatEnd`/`deleteCombat` the module rewrites
each running rounds effect to seconds from its remaining rounds, using
`ROUNDS_PER_TURN` / `TURN_SECONDS` promoted from `formation/constants.mjs` to lib
(a second feature now needs them). Foundry's `ActiveEffect.registry` does the ageing
(combat events and `updateWorldTime`); the module reacts to `duration.expired`
flipping true in `updateActiveEffect` — chat notice, status removal, summon prompt —
and offers a world setting to delete expired spell effects instead of leaving them
suppressed (core's `CONFIG.ActiveEffect.expiryAction` is left alone; `isSuppressed`
already defers to `duration.expired`, so an expired effect stops applying). The
Effects tab's `effectClock` reads these fields today and GAINS grouping by `castId`.
The formation record's `spells[]` countdown (`formation/turn-engine.mjs`) becomes a
projection of these effects when `mayAdvanceWorldTime()` is true (then the registry
ages them on world time) and keeps its own tick when it is false — keyed on that
setting, not on "a combat is running", or two clocks age one spell.

**Summons:** the `summon` row resolves a creature (`lib/library.mjs` by cookbook id or
uuid, or a filter by type/HD for "summon a creature of up to N HD"), creates tokens
adjacent to the caster (click-to-place is a later polish), stamps
`flags.acks-extras.summonedBy` (`SUMMON_FLAG` moves from
`character-sheet/constants.mjs` to lib now that it has a second writer) + `summon:
{castId, casterUuid, effectUuid, format, control}`, and adds a `spellEffect` (role
`summon`) on the summoned actor. Expiry or dismissal raises a GM prompt listing the summoned tokens;
confirming deletes the tokens and the unlinked actors the cast created — never
automatically (§10c), with an opt-in world setting for auto-dismissal of unlinked
summons only. The character sheet's party cell and the initiative card read the flag
they already read. Control (JJ formats + `CONTROL_KINDS`) is recorded on the effect
and shown; loss of control is a per-spell clause the Judge resolves from the card.

### Magic items

`flags["acks-extras"].magicItem` DataModel (`magic-items/magic-item-data.mjs`) on core
`item`, `weapon` and `armor` — a wand is an `item` with powers, a sword +1 stays a
`weapon` whose bonus rides the existing `acks-extras.variation` (`magical.*`) and
whose powers ride this flag. Fields: `kind: choice(MAGIC_ITEM_KINDS)`, `powers:
[{kind: choice(spell|effect|bonus|proficiency|classPower|special), spell:
spellRefField(), casterLevel, rows: effectsField(), activation: {kind:
choice(ACTIVATION_KINDS), frequency: SPELL_LIKE_FREQ, time: CASTING_TIME_SHAPES,
commandWord, cancellation: choice(none|command|duration|dispel)}, charges: {value,
max, rechargeable, rechargeBy}}]`, `cursed: {is, revealed, removal}`, `drawbacks: []`,
`restrictions: {classes, alignments, attributes}`, `lifespan`, `set: {key}`,
`traits: []`, `corruption`, `formula: {known, source}`, `sample: bool`, `baseCost:
[{effectType, cost}]` (imported, the RR ch. 8 vocabulary), `scroll: {language,
levelsRemaining, protection}`, `potion: {miscibility}`. Apparent value, rarity,
identification state and aura stay in the markets flag (owned there; `isMagical`
already reads it). Use flow (`magic-items/use.mjs`): sheet/inventory "Use" →
resolve power → `castSpell` with the item as source → decrement charge / consume a
one-use item / tick a periodic or triggered power; cursed reveal and user
restrictions gate the use with a GM prompt. Sheet: an injected fieldset on core's
item sheets (the monsters feature's injected-fieldset pattern) and a tab on the
extras `AcksItemSheet`, with a power editor (the shared effect-row editor). Content:
JJ ch. 4 (~155 entries, Base Cost/Apparent Value lines) and the Treasure Tome
(~1,220 entries whose Mechanics block — activation time, frequency, cancellation —
maps straight onto `activation`). JJ wins on conflict by an EXPLICIT source-priority
rule in the binder (the register's `editions` is a per-definition acks1→acks2
revision link, not book-over-book precedence). Generation: JJ classic, JJ heroic and TT gritty tables become chained
cookbook RollTables (the 2026-09-23 chart-routing ruling) whose results resolve
library items by locator, behind a "Roll a magic item" macro; JJ trait tables and TT
appendices (traits, corruption, potion miscibility, item generation) import as
rules tables. `register/_refs/magicProperty.json` (302 tokens, no nodes) gains its
definition nodes from these entries, which also closes the monster spoils'
`researchEffects` loop.

### Magical research

`acks-extras.research` Item sub-type (`research/research-data.mjs`) owned by the
researcher, so it travels with the character and a GM ledger app lists every
project in the world. Fields: `kind: choice(RESEARCH_KINDS)`, `status:
choice(planned|active|paused|complete|failed)`, `subject` (a spell ref, an item
draft in the `magicItem` shape, a creature design record — the RR ch. 8 construct /
crossbreed field list — a subject ref for necromancy, a ritual ref, an item to
identify, or an experiment), `costs: {component: {required, covered: {components:
refs to spoil items, substitutes, compounds}}, material, research}` (computed from the
imported `acks.magicResearch` tables by kind, spell level, bonus or effect type),
`rate: {base, assistants: [{ref, mode: add|supervise}]}`, `throw: {base, modifiers:
[{source, value}], result}`, `facilities: {required: choiceSet(FACILITIES), have}`,
`experiment: {method, advantages, breakthrough, mishap, mutation}`, `progress:
{started, spent, due}`, `outcome: {ref}`, `xp`. A project written by an earlier
release is ADOPTED on read — a missing field takes its default and
`progress.started` is filled from the first advance — never gated on a version
epoch (§10b). Time: `lib/world-time.mjs`
`onWorldTimeAdvanced` accrues progress on the active GM only; completion raises the
throw as a GM action (§10c — mishaps, mutations and lost costs are applied by the
Judge from the card, never by the clock). Facilities resolve through the henchmen
"has X" chain (owning module → actor flag → inventory marker item → ask the GM), so
a future strongholds module takes the first step transparently. Outcomes: a spell
(added to the repertoire/spellbook), a magic item document, a construct/crossbreed/
undead actor stamped with its control rule, a ritual known (ritual repertoire ladder
imported), identification written into the markets flag (the ladder's
`magicResearch` method becomes real), breakthrough XP. Extensions in the same
document: AX1 arcanogenesis (a design + genesis vat), AX7 compounds (a substitution
layer over components) and magic-item research, overcasting's calamity/transgression
tables (JJ ch. 16, optional-rule setting), places of power (JJ ch. 2) as a location
flag the throw modifiers read. Divine and arcane power are ledgers on the actor
adjusted by GM tools; congregation-scale generation (RR §VIII.9) waits for the domain
module family and is recorded in ROADMAP. Spellcasting services (RR ch. 4, JJ ch. 7)
are a markets/henchmen bridge: a spell service row priced by the imported
availability table, fulfilled by a `castSpell` from the hired caster.

## Open questions and decisions to record in DECISIONS.md at build time

1. **Reversed forms as one document or two.** Proposed: one Item per printed entry
   heading, pairs linked by `reverseOf`, the cast dialog offering both — matches the
   page and the oracle's asterisked headings. The alternative (one item with a
   reversed mode) would need per-mode effect rows and breaks `lists[]`.
2. **Expiry action.** Proposed: leave core's `CONFIG.ActiveEffect.expiryAction`
   alone, react to `duration.expired`, offer deletion as a world setting. Setting
   the global would change how every other module's effects behave.
3. **Summon placement.** Proposed: adjacent auto-placement in release 2; click-to-
   place as polish. Dismissal always prompts; auto-dismissal only for unlinked
   summons and only by setting.
4. **Where research projects live.** Proposed: owned by the researcher (travels with
   the character, player-visible), with a GM ledger app over the world. The
   alternative (world items in a folder) hides progress from players.
5. **Magic-type documents over builder rows.** Proposed: documents publish to
   their own `acks.magicTypes` doc and `builderTables()` merges them over the
   imported `magicTypes` rows by key; the rows never retire (a Judge who imported
   only the JJ ch. 12 grids still has a builder). Evidence for the document: the
   JJ ch. 15 knobs a row cannot hold (shade, resources, ceremony, spell list).
   Rejected: publishing documents into `acks.classBuilder` at WORLD priority — it
   races the importer's WORLD writer and a layer replaces the table whole.
6. **The shared effect-row editor** is proposed for `lib/apps/` so abilities gain it
   too (they have only a roll editor today). Scope creep is real; the alternative is
   a magic-only editor promoted later — "promoting shared machinery into lib is
   standing permission" (TOOLCHAIN §6) argues for lib from the start.
7. **HFH name conversion.** ACKS I spell and class names in the HFH lists resolve
   through `register/_refs/conversion.json`; unknown names degrade to plain text at
   runtime (the register's own rule). Expect a resolver pass while authoring.
8. **Wonderworker and studious-list oracle discrepancies** (rules pass): the
   printed page wins; settle each while authoring the register and note it in the
   register row, never in a repo doc.
9. **Model routing for the build**: `scout` inventories (stat-line shapes, list
   membership), `implementer` applies mechanical multi-file changes (enum plumbing,
   lang keys, pack data), `architect` rules on the data model and the engine seams
   before code, `live-tester` is avoided for the pane-driven walks (it recurses —
   drive the Foundry pane directly), `doc-scribe` keeps gallery/changelog/guides.
   Cheap-agent sweeps cost their review; the DECISIONS entries they stage are read
   against the source before they merge.
10. **Code enum or open vocabulary.** The owner asked for dedicated enums on the
    weapon-type pattern; the IP doctrine's option-list clause says a list a reader
    picks from is content. Proposed line: engine-dispatch keys are code, pick-lists
    ship empty and fill from the page (schools, elements, shades, components,
    transform aspects, detect modes, protection kinds, wall properties). Strongest
    counter-argument, MEDIUM: the family already ships `DAMAGE_TYPES`,
    `CONDITION_KEYS` and `EFFECT_KEYS` as code and these keys are common words, so
    the membership of the 14 school tags is arguably structure too — the reply is
    that it is the membership, not the words, that the page supplies, and the
    existing enums each back an engine branch. If the owner rules them code, only
    the file the members live in changes.
11. **Spell effects as a flag or a sub-type.** Proposed: the flag (Tracking). The
    sub-type is taken only when a per-write validation or a native per-type config
    sheet is needed, and the DECISIONS entry names which.

## What this scope deliberately leaves out

Domains at War battle resolution (DECISIONS §15), congregation-scale divine power
generation (the domain module family), an OSE spell recipe (OSE's own spell text is
not in scope), and any value read off a page in any shipped file.
